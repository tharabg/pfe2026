Système Intelligent d'OCR avec Pipeline ETL et Architecture Microservices
================================================================================

TITRE DU PROJET:
"Conception et implémentation d'un système intelligent de reconnaissance
optique de caractères (OCR) multilingue avec pipeline ETL pour l'extraction
et la translittération de données de documents officiels"

MÉTHODOLOGIE: CRISP-DM + Agile/Scrum
NIVEAU: Projet de Fin d'Études (Ingénieur)
DOMAINE: Intelligence Artificielle, Ingénierie Logicielle, MLOps

1. BUSINESS UNDERSTANDING (Compréhension du Problème Métier)
================================================================================

1.1 CONTEXTE DU PROJET
   Entreprise: TopNet (Société Tunisienne)
   Besoin: Automatiser le traitement des documents officiels

1.2 PROBLÈME IDENTIFIÉ
   ❌ AVANT: Traitement manuel des documents (CIN, factures, contrats)
      - Temps: ~5 minutes par document
      - Coût: Personnel dédié
      - Erreurs: ~15% taux d'erreur humain
      - Scalabilité: Impossible de traiter en volume

   ✅ APRÈS: Système automatisé intelligent
      - Temps: ~3 secondes par document
      - Coût: Amortissement infrastructure
      - Erreurs: ~5% (objectif)
      - Scalabilité: Traitement en batch possible

1.3 OBJECTIFS DU PROJET

   OBJECTIF PRINCIPAL (SMART):
   "Développer un système d'OCR multilingue capable de:
    - Classifier automatiquement les types de documents (CIN, Facture, Contrat)
    - Extraire les champs structurés avec confiance > 85%
    - Translittérer l'arabe en latin et traduire en anglais
    - Traiter 1000+ documents/jour en production"

   OBJECTIFS SPÉCIFIQUES:
   1. Classification: Accuracy ≥ 95%
   2. OCR: Character Accuracy ≥ 92%
   3. Temps réponse: < 5 secondes par document
   4. Uptime: 99.5%
   5. Scalabilité: Traitement parallèle possible

1.4 PARTIES PRENANTES
   - Utilisateurs finaux: Agents administratifs TopNet
   - Management: Directeurs IT/Finance
   - Décideurs: CTO, Directeur technique
   - Régulateurs: Conformité données sensibles

1.5 RISQUES IDENTIFIÉS
   ⚠️  Données sensibles (documents d'identité)
       → Solution: Chiffrement, conformité RGPD
   ⚠️  Performance en production
       → Solution: Caching, CDN, optimisations
   ⚠️  Qualité OCR variable selon document
       → Solution: Validation humaine en cas de doute
   ⚠️  Maintenance des modèles ML
       → Solution: MLOps, versioning, monitoring

2. DATA UNDERSTANDING (Compréhension des Données)
================================================================================

2.1 SOURCES DE DONNÉES
   Type 1: CIN (Carte d'Identité Nationale Tunisienne)
      - Format: JPG, PNG (résolution: 400x600 pixels min)
      - Champs: Nom, Prénom, Numéro CIN, Date naissance, Validité
      - Langue: Arabe + Latin
      - Volume: ~2000 images (données de test)

   Type 2: Factures/Invoices
      - Format: JPG, PDF (résolution: variable)
      - Champs: Numéro facture, Date, Montant, Client, TVA
      - Langue: Français + Arabe
      - Volume: ~1000 images

   Type 3: Contrats
      - Format: JPG, PDF (résolution: variable)
      - Champs: Parties, Date signature, Montant, Conditions
      - Langue: Français
      - Volume: ~500 images

2.2 CARACTÉRISTIQUES DES DONNÉES
   ✓ Structured (champs bien définis)
   ✓ Semi-structured (mise en page variable)
   ✓ Multilingual (Arabe, Français, Anglais)
   ✓ Multimodal (images + texte)

2.3 QUALITÉ DES DONNÉES
   Enjeux:
   - Résolution variable (parfois faible qualité)
   - Orientation incorrecte (pages tournées)
   - Bruit (taches, rayures)
   - Éclairage inégal
   - Texte en scripts multiples

   Solutions:
   - Augmentation de données (rotation, flou, etc.)
   - Prétraitement robuste (normalisation, débruitage)
   - Validation croisée

2.4 DONNÉES SENSIBLES
   ⚠️  Information personnelle (CIN numbers, noms)
   📋 Conformité: RGPD, lois tunisiennes
   🔒 Mesures: Chiffrement, anonymisation, audit logs

3. DATA PREPARATION (Préparation des Données)
================================================================================

3.1 ÉTAPES DE NETTOYAGE
   Phase 1: Collecte
      - Organiser en dossiers: train/ test/ val/
      - Ratio: 70% train, 15% test, 15% validation

   Phase 2: Validation
      - Vérifier format des images
      - Supprimer fichiers corrompus
      - Vérifier labels cohérents

   Phase 3: Normalisation
      - Redimensionner toutes images à 224x224
      - Convertir au format RGB standard
      - Normaliser intensité pixel (0-1 ou 0-255)

   Phase 4: Augmentation (Data Augmentation)
      - Rotation: ±15 degrés
      - Horizontal flip: certains documents
      - Zoom: 0.8x - 1.2x
      - Luminosité: ±10%
      - Objectif: Augmenter dataset 2-3x

3.2 FEATURE ENGINEERING
   Image Features (pour classification):
   - Texture features: LBP (Local Binary Patterns)
   - Color histograms: Distribution couleurs
   - Edge detection: Contours document
   - HOG (Histogram of Oriented Gradients)

   Text Features (après OCR):
   - Bag of Words (BOW)
   - TF-IDF scores
   - Named Entity Recognition (NER)
   - Keywords extraction

3.3 ORGANISATION FINALE
   data/
   ├── raw/               ← Données originales
   ├── processed/         ← Données nettoyées
   ├── preprocessed/      ← Images augmentées
   ├── train/             ← Set d'entraînement
   ├── test/              ← Set de test
   └── val/               ← Set de validation

4.2 MODÈLES DÉTAILLÉS

   MODÈLE 1: CLASSIFICATION (Document Type)
   ─────────────────────────────────────────
   Architecture: CLIP Vision Language Model
   Base: ViT-Base-Patch32 (OpenAI)

   Pourquoi CLIP?
   ✓ Multimodal (image + text)
   ✓ Transfert learning (pré-entraîné)
   ✓ Zéro-shot capable (pas besoin fine-tuning complet)
   ✓ Robuste à variations d'images

   Processus:
   1. Encoder image: ViT (Vision Transformer)
   2. Encoder text: BERT
   3. Matcher: Maximiser similarité cosinus
   4. Output: Scores pour chaque classe

   Métrique: Accuracy, Precision, Recall, F1-score
   Objectif: ≥ 95% accuracy


   MODÈLE 2: OCR (Extraction de Texte)
   ──────────────────────────────────
   Framework: PaddleOCR

   Pourquoi PaddleOCR?
   ✓ Multilingue (50+ langues dont Arabe)
   ✓ Détection automatique orientation
   ✓ Open source, gratuit
   ✓ Performance comparable à Tesseract
   ✓ Détection de zones (bounding boxes)

   Pipeline PaddleOCR:
   1. Text Detection: Repérer zones texte
   2. Text Recognition: Reconnaître caractères
   3. Angle Classification: Corriger orientation
   4. Output: Texte + Confidence scores

   Métrique: Character Accuracy, Word Accuracy
   Objectif: ≥ 92% character accuracy


   MODÈLE 3: NLP & EXTRACTION
   ─────────────────────────
   Tool: spaCy

   Fonction:
   1. Named Entity Recognition (NER)
      - Identifier: Noms, dates, organisations
      - Utilité: Valider extraction

   2. Regex Patterns
      - CIN: /\d{8}/
      - Email: /[\w\.-]+@[\w\.-]+\.\w+/
      - Phone: /\+?216[0-9]{8}/
      - Dates: /\d{1,2}\/\d{1,2}\/\d{4}/

   3. Field Validation
      - Vérifier format correct
      - Cross-check données


   MODÈLE 4: TRANSLATION (LLM)
   ──────────────────────────
   Tool: Mistral/Ollama

   Tâches:
   1. Translittération Arabe→Latin
      Exemple: "محمد" → "mohammad"
      Mapping: Caractère arabe → Caractère(s) latin

   2. Traduction multilingue
      Exemple: "السلام عليكم" → "Hello"
      Utilise: LLM pour contexte

   3. Suppression diacritiques
      Exemple: "مَرْحَبًا" → "مرحبا"

4.3 COMPARAISON MODÈLES ALTERNATIFS

   CLASSIFICATION:
   ├─ CLIP ✓ (CHOISI)
   ├─ ResNet-50 (moins performant sur multimodal)
   ├─ EfficientNet (bon mais pas multimodal)
   └─ YOLOv8 (focused détection, pas classification)

   OCR:
   ├─ PaddleOCR ✓ (CHOISI - meilleur pour arabe)
   ├─ EasyOCR (bon mais plus lent)
   ├─ Tesseract (ancien, moins performant)
   └─ Google Cloud Vision (API payante)

   TRANSLATION:
   ├─ Mistral ✓ (CHOISI - local, open source)
   ├─ GPT-4 (coûteux, API)
   ├─ Google Translate (API, latence)
   └─ LibreTranslate (moins performant)

5. EVALUATION (Évaluation des Modèles)
================================================================================

5.1 MÉTRIQUES DE PERFORMANCE

   CLASSIFICATION:
   ┌─────────────────────────────────────────┐
   │ Accuracy = (TP+TN)/(TP+TN+FP+FN)       │
   │ Precision = TP/(TP+FP)                 │
   │ Recall = TP/(TP+FN)                    │
   │ F1-Score = 2 × (Precision×Recall)/     │
   │            (Precision+Recall)          │
   │ Confusion Matrix: Visualiser erreurs   │
   └─────────────────────────────────────────┘

   OCR:
   ┌─────────────────────────────────────────┐
   │ Character Error Rate (CER): %           │
   │   CER = (S+D+I)/N                       │
   │   S=substitution, D=deletion, I=insert  │
   │ Word Error Rate (WER): %                │
   │ Confidence Score: moyenne (0-1)         │
   └─────────────────────────────────────────┘

   EXTRACTION:
   ┌─────────────────────────────────────────┐
   │ Field Extraction Rate: Champs extraits  │
   │ Validation Rate: Champs corrects        │
   │ Precision par champ: Exactitude         │
   └─────────────────────────────────────────┘

   SYSTÈME GLOBAL:
   ┌─────────────────────────────────────────┐
   │ End-to-End Accuracy: Document complet   │
   │ Processing Time: Latence moyenne        │
   │ Throughput: Documents/seconde           │
   │ Uptime: % disponibilité                 │
   └─────────────────────────────────────────┘

5.2 VALIDATION CROISÉE (Cross-Validation)
   Technique: K-Fold Cross-Validation (K=5)

   Processus:
   1. Diviser données en 5 folds
   2. Entraîner modèle sur 4 folds
   3. Tester sur 1 fold
   4. Répéter 5 fois
   5. Moyenne des résultats

   Avantage: Éviter overfitting, utiliser toutes données

7.2 PIPELINE DE DONNÉES - DÉTAIL

   INPUT: Document image (JPG/PNG)
   │
   ├─ Step 1: VALIDATION
   │  └─ Vérifier format, size, corrupted
   │
   ├─ Step 2: PREPROCESSING
   │  ├─ Load image (OpenCV)
   │  ├─ Resize to 224x224
   │  ├─ Deskew (correction rotation)
   │  ├─ Denoise (bilateral filter)
   │  ├─ Contrast enhancement (CLAHE)
   │  └─ Output: Image normalisée
   │
   ├─ Step 3: CLASSIFICATION
   │  ├─ Load CLIP model
   │  ├─ Encode image + text descriptions
   │  ├─ Compute similarity scores
   │  ├─ Argmax pour classe
   │  └─ Output: Type + Confidence
   │
   ├─ Step 4: OCR
   │  ├─ Load PaddleOCR model
   │  ├─ Text detection (find zones)
   │  ├─ Text recognition (recognize)
   │  ├─ Angle correction (orientation)
   │  └─ Output: Text + Confidence + Boxes
   │
   ├─ Step 5: EXTRACTION STRUCTURÉE
   │  ├─ Load spaCy + Regex patterns
   │  ├─ NER: Identifier entités
   │  ├─ Pattern matching: Champs clés
   │  ├─ Validation: Format, coherence
   │  └─ Output: Structured fields JSON
   │
   ├─ Step 6: TRANSLATION
   │  ├─ Load Mistral model (Ollama)
   │  ├─ Transliterate (Ar→Latin)
   │  ├─ Remove diacritics
   │  ├─ Translate to target language
   │  └─ Output: Translated fields
   │
   ├─ Step 7: VALIDATION & STORAGE
   │  ├─ Validate all fields
   │  ├─ Check business rules
   │  ├─ Store in PostgreSQL
   │  ├─ Index for search
   │  └─ Output: Stored document
   │
   └─ OUTPUT: Structured data in DB
